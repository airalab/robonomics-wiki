Дерево устройств описывает вашу установку в облаке Robonomics: объект, его помещения и устройства в них. Каждая часть — это узел. Блокчейн хранит структуру установки и последнее состояние каждого узла. Для больших объёмов данных дерево не предназначено.

В рантайме дерево устройств — это паллет `CPS` (cyber-physical systems, киберфизические системы). Полный технический справочник: [README паллета CPS](https://github.com/airalab/robonomics/blob/master/frame/cps/README.md).

## Узлы

- У каждого узла есть номер (`NodeId`). Номера растут по одному и никогда не используются повторно.
- У узла может быть родитель. Узел без родителя — корневой.
- Узел хранит два поля, оба необязательные:
  - `meta`: описание, которое меняется редко, до 1 КиБ.
  - `payload`: текущее состояние, до 8 КиБ.
- Оба поля — просто байты. Формат выбираете вы, например JSON.
- Родитель узла не меняется. Чтобы перенести узел, создайте новый и удалите старый.
- У узла может быть не больше 100 детей. Удалить можно только узел без детей.

## Scope

Scope — это часть дерева, которой владеет один аккаунт.

- Создавая корневой узел, вы одновременно создаёте Scope и становитесь его владельцем.
- Каждый узел относится к ближайшему корню Scope над ним, а если он сам корень Scope — к своему Scope.
- Узел внутри вашего дерева можно сделать корнем нового вложенного Scope. Вложенный Scope — жёсткая граница: внешний владелец и внешние права доступа внутри него не действуют. Одно исключение: владелец Scope, который непосредственно окружает вложенный, может его заменить.
- Владелец Scope не меняется. Чтобы передать Scope, его заменяют: аккаунт с правом создать Scope на его корневом узле вызывает `create_scope`. Появляется новый ID Scope, вызывающий становится владельцем, а все старые записи доступа удаляются.
- Глубина Scope — не больше 32 узлов, считая от узла до корня его Scope. Всё дерево может быть глубже.
- Scope исчезает, только когда удаляют его корневой узел.

## Доступ

Владелец Scope может делать внутри него всё. Другим аккаунтам нужна запись доступа, и выдать её может только владелец.

| Право | Разрешает |
|---|---|
| `Write` | `set_meta` и `set_payload` |
| `CreateScope` | `create_scope` |

- Запись действует в одном из двух режимов: `Node` (один узел) или `Subtree` (узел и всё под ним, кроме вложенных Scope).
- В одном Scope — не больше 32 записей доступа.
- Создание детей, удаление узлов, выдачу и отзыв доступа делегировать нельзя. Это может делать только владелец.

В дорожной карте 5.0 запланированы новые права (для транзакций, хранилища и вычислений). В рантайме их пока нет.

## Аккаунты узлов

К узлу можно привязать один аккаунт — его идентичность (identity). Обычно это собственный ключ устройства. Один аккаунт может быть идентичностью только одного узла, поэтому узел можно найти по аккаунту устройства.

- Задать или снять идентичность может только владелец Scope. Права `Write` для этого мало.
- Если идентичность — не сам вызывающий, аккаунт идентичности должен подписать разрешение (permit). Разрешение — это SCALE-кодировка `(b"robonomics:cps:node-identity:v1", genesis_hash, scope_id, valid_until)`, подписанная как сырые байты, без обёртки `<Bytes>`.
- Разрешение действует не больше суток (14,400 блоков). Оно не расходуется: работает в своём Scope, пока не истечёт срок. Замена Scope делает старые разрешения недействительными.
- Новый корневой узел принимает идентичностью только собственный аккаунт вызывающего.
- При удалении узла его идентичность снимается.

## Вызовы

Polkadot.js показывает эти имена в camelCase, например `cps.createNode`.

| Вызов | Аргументы | Кто может вызвать |
|---|---|---|
| `create_node` | `parent_id` (необязательно), `meta` (необязательно), `payload` (необязательно), `identity` (необязательно: аккаунт и, если нужно, разрешение) | Корневой узел: любой аккаунт, он становится владельцем Scope. Дочерний узел: владелец Scope родителя. |
| `set_meta` | `node_id`, `meta` (`None` удаляет поле) | Обладатель `Write` |
| `set_payload` | `node_id`, `payload` (`None` удаляет поле) | Обладатель `Write` |
| `delete_node` | `node_id` | Владелец Scope. У узла не должно быть детей. Удаление корня Scope удаляет Scope и его записи доступа. |
| `create_scope` | `node_id` | Обладатель `CreateScope`. В корне вложенного Scope — также владелец окружающего Scope. |
| `grant_access` | `node_id`, `principal`, `capability` (`Write` или `CreateScope`), `mode` (`Node` или `Subtree`) | Владелец Scope |
| `revoke_access` | `node_id`, `principal`, `capability` | Владелец Scope |
| `set_identity` | `node`, `identity`, `permit` (необязательно) | Владелец Scope |
| `clear_identity` | `node` | Владелец Scope |

События: `NodeCreated`, `MetaSet`, `PayloadSet`, `NodeDeleted`, `ScopeCreated`, `ScopeDeleted`, `AccessGranted`, `AccessRevoked`, `IdentitySet`, `IdentityCleared`.

## Чтение дерева

- Простое чтение — это запросы к хранилищу: `cps.nodes`, `cps.meta`, `cps.payload`, `cps.children`.
- У паллета есть и view-функции (им нужны метаданные V16, которые сеть отдаёт):
  - по номеру узла: `resolve_scope`, `has_capability`, `identity_of`, `node_by_identity`;
  - по аккаунту устройства: `parent`, `children`, `meta`, `payload`, `scope_of`, `address_capability`. Они завершаются ошибкой `MissingProjectedIdentity`, если у какого-то узла в результате нет идентичности.
- В JavaScript view-функции доступны как `api.view.cps.*`; для этого нужна версия `@polkadot/api` с поддержкой view-функций. В Rust они есть в типизированном крейте `robonomics-runtime-subxt-api`.

## Лимиты и комиссии

| Лимит | Значение |
|---|---|
| Размер `meta` | 1,024 байта |
| Размер `payload` | 8,192 байта |
| Глубина Scope | 32 узла |
| Детей у узла | 100 |
| Записей доступа в Scope | 32 |
| Срок действия разрешения идентичности | 1 сутки (14,400 блоков) |

Это константы рантайма. Чтобы их изменить, нужно обновление рантайма.

Депозита за хранение дерево устройств не берёт. Вы платите обычную комиссию за транзакцию, и она растёт с размером данных. Например, на момент написания корневой узел со 100 байтами `meta` и 100 байтами `payload` стоит около 0.0003 XRT.

## Инструменты

- Консольная утилита `cps` и Rust-библиотека `libcps` покрывают всё дерево устройств. См. [Клиентские библиотеки](/docs/client-libraries/#cps-command-line-tool).
- Подойдёт и любой клиент, который умеет отправлять экстринзики, например `@polkadot/api`.
- Если устройство не может работать с блокчейном напрямую, см. [Подключение устройств](/docs/connect-devices/).

## Что дальше

С подписками (5.0, в разработке) владелец Scope сможет оплачивать транзакции устройств в дереве. Тогда датчик сможет писать данные, не держа XRT сам. В рантайме этого пока нет.
